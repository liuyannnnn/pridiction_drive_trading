# PM 多策略交易系统执行计划

## 1. 阶段目标

- 阶段 A：完成需求、设计、计划文档，统一实现边界。
- 阶段 B：沉淀 Polymarket 与 Goalserve 离线文档索引。
- 阶段 C：搭建后端最小可运行框架与基础数据层。
- 阶段 D：接入行情链路与重采样落库。
- 阶段 E：完成策略引擎与模拟交易闭环。
- 阶段 F：完成真实交易链路与风控。
- 阶段 G：前端联调并验收交付。

## 2. 任务拆解

### 阶段 A 文档基线
- 产出 requirements/design/plan 三份文档。
- 将需求条目映射到可验证验收项。
- 建立版本号与后续变更记录机制。

### 阶段 B 文档镜像
- 拉取 PM 文档到 `polyapi/`，按主题归档。
- 拉取 Goalserve 文档到 `gsapi/`，按主题归档。
- 生成索引文件，建立“能力 -> 文档位置”映射。

### 阶段 C 骨架
- 初始化后端目录结构与配置模型。
- 提供健康检查与最小比赛查询接口。
- 接入 PostgreSQL/Timescale 与 Redis 基础连接。
- 建立数据库初始化脚本。

### 阶段 D 数据链路
- PM 赛事筛选抓取（成交量阈值 + 未来 24h）。
- PM WS 与 Goalserve 通道接入。
- 标准化事件模型与异步分发。
- Redis 高频落点 + 分钟重采样落库。

### 阶段 E 策略与模拟
- 建立策略接口标准与策略加载机制。
- 建立策略 Worker 隔离运行机制。
- 模拟执行器支持下单、成交、撤单、持仓、PnL。

### 阶段 F 真实交易
- 账户别名配置与认证读取。
- 真实执行器 API 接入与状态回写。
- 风控规则：余额、限额、交易窗口、熔断。

### 阶段 G 联调
- 左侧比赛区实时数据接入。
- 中间详情区图表、扩展数据、成交与日志接入。
- 右侧交易区账户、策略参数、模式切换接入。
- 端到端联调与问题回归。

## 3. 每阶段验收门禁

- 必须具备可运行证明（命令、日志、接口响应）。
- 必须补充最小测试（单测或集成验证脚本）。
- 必须更新文档（接口、配置、变更点）。
- 门禁通过后进入下一阶段。

## 4. 风险与回退

- 外部接口变动：通过 adapter 层隔离，快速热修映射。
- WS 不稳定：自动重连 + 断点补拉 + 降级为轮询。
- 策略失控：策略级熔断 + 统一风控兜底。
- 真实交易风险：默认模拟、手动开关、逐步放量。

## 5. 本轮实现范围（即刻执行）

- 完成阶段 A 全部交付。
- 完成阶段 B 的离线目录与索引。
- 完成阶段 C 的后端框架、配置模板、数据库脚本与最小 API。
- 提供本地启动与验证说明，为下一轮阶段 D 做准备。
