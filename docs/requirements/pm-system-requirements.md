# PM 多策略交易系统需求文档

## 1. 背景与目标

- 构建基于 Polymarket 的多策略交易系统，覆盖模拟交易与真实交易。
- 初期市场范围限定为足球与篮球。
- 在尽量不改动现有前端布局的前提下，完成后端能力与前后端联动。

## 2. 业务范围

### 2.1 比赛数据
- 左侧比赛区按状态分为 live 与 pre。
- 定时抓取成交量高于阈值的候选比赛，pre 仅保留未来 24 小时内赛事。
- live 比赛通过 WS 实时刷新盘口与比赛信息。

### 2.2 赛事详情
- 中间区域展示赛事元数据、盘口变化图、成交记录与策略日志。
- 图表展示 moneyline outcome prices 时间变化。
- 详情区新增外部数据块（Goalserve），含更新时间、比分、阵容、近期战绩、赔率。

### 2.3 交易能力
- 模拟交易：选择策略与参数后运行，产出持仓、成交、日志、收益。
- 真实交易：可按 PM 账户别名选择账户配置，展示可用资金与持仓信息。
- 真实交易支持下单、取消、成交状态同步与日志追踪。

## 3. 外部系统需求

### 3.1 Polymarket
- 接入 REST 获取比赛与市场列表。
- 接入 WS 获取 live 盘口与变更数据。
- 接入交易 API 支撑真实交易执行。

### 3.2 Goalserve
- 接入实时数据通道补充 live 赛事信息。
- 接入 HTTP 下载历史数据并落库。
- 维护字段映射以统一到内部领域模型。

## 4. 非功能需求

### 4.1 性能与并发
- 高频 WS 数据优先写 Redis，再按分钟重采样落库。
- 数据库读写应基于异步驱动，避免策略高并发阻塞。
- 策略运行需隔离，互不干扰，支持并发扩展。

### 4.2 可维护性
- 每个策略独立文件或目录，满足后续新增策略能力。
- 策略接口统一，显式声明可配置参数。
- 接入层、事件层、策略层、执行层边界清晰。

### 4.3 安全性
- PM 密钥类信息仅保存在环境变量或本地安全配置。
- 日志默认脱敏，不输出敏感认证数据。
- 真实交易必须有显式开关与风控阈值。

## 5. 数据匹配需求（PM vs Goalserve）

- 需解决队名全称/缩写差异、时区差异、联赛命名差异。
- 匹配采用多阶段评分：名称归一化 + 时间窗口 + 联赛置信度。
- 低置信度结果不直接进入交易链路，进入待确认流程。
- AI 可作为低置信样本的辅助重排，不作为唯一判定依据。

## 6. 策略标准

- 必须具备：读取标准化赛事数据、生成交易信号、记录日志、统计结果。
- 必须提供：策略参数定义、参数默认值、参数校验规则。
- 必须支持：模拟与真实模式统一策略输入输出协议。

## 7. 验收标准

- 可展示 live/pre 比赛，并符合筛选条件（成交量阈值、24h 限定）。
- live 比赛盘口与比分可实时刷新，分钟级行情可查询。
- 策略可并行运行并输出可追踪日志与交易记录。
- 模拟交易完整闭环可用，真实交易在风控条件下可执行。
- 前端三区域均由后端真实数据驱动，满足页面功能描述。
